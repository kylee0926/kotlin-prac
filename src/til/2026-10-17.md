### 수신 객체 (reveiver)

수신 객체는 함수가 호출되는 대상이고, "." 앞에 있는 걸 말함

```kotlin
val shapes = listOf("원", "삼각형", "사각형")
shapes.first() // 여기서 shapes가 수신 객체
```

그러면 확장 함수는 어떻게 만들어야 될까?

* fun 클래스명.함수명() 의 형태로 이용

```kotlin
fun String.bold(): String = "<b>$this</b>"
fun main(){
    println("hello".bold())
}
```

String 클래스에 bold()라는 메소드를 만든다. 

"hello"가 수신 객체 역할을 하는데, "this"는 수신 객체에 접근하는 문법이라고 생각하면 된다.

## Scope Functions

스코프 함수는 어떤 객체 주변에 임시 스코프 블록을 만들어서, 그 안에서 코드를 실행할 수 있게 해주는 함수

장점으로는 그 안에서 객체 이름을 매번 쓰지 않고, 객체를 this나 it으로 부름

스코프 함수는 총 5개임
* let
    * null 체크 후 그 값으로 뭔가 할 때
    * nullable 변수를 null이 아닐때만 쓰고 싶을 때 쓴다.
* apply
    * 객체를 만들면서 바로 설정할때
    * 객체를 생성하는 시점에 속성 설정이나 초기화를 한 번에 끝내고 싶을때 쓴다.
* run
    * 객체로 작업하고 결과값을 얻을 때
    * apply랑 비슷하게 this를 쓰지만, 반환하는게 객체가 아니라 람다의 마지막 결과값
    * 객체로 이것저것하고, 최종 결과를 받고 싶을때 쓴다.
* also
    * 중간에 덤으로 무언가 할 때
    * 객체를 가지고 부가적인 작업을 하고, 객체는 다시 돌려준다.
    * also안에서는 it으로 객체에 접근하며, 중간에 값이 어떻게 바뀌는지 볼 때 쓴다.
* with
    * 한 객체의 함수를 여러 번 호출할때
    * with는 다른 넷과 달리 확장함수가 아니며, 객체.with{} / with (객체) {}로 객체 인자를 넘김
    * 객체 이름이 길수록 코드가 읽기 쉬어져서 실수가 줄어드는 효과가 있다.


### let

```kotlin
fun greet(name: String): String = "안녕, $name!"

fun main(){
    val name: String? = "철수"
    
    val msg1 = if (name != null) greet(name) else null
    var msg2 = name?.let{greet(it)}
}
```
msg2에서 name이 null이 아니면 greet() 함수를 실행한다는 의미이다.
그리고 it은 수신 객체로서 name을 가르킴

### apply

```kotlin
class Client {
    var token: String? = null
    fun connect() = println("연결됨")
    fun authenticate() = println("인증됨")
}

// apply 없이
var client1 = Client()
client1.token = "abcd"
client1.connect()

//apply 사용
val client2 = Client().apply{
    token = "abcd"
    connect()
    authenticate()
}
```

블록 안에서는 this로 객체에 접근하는데, "this."는 생략할 수 있어서 token, connect()처럼 바로 쓸 수 있다.
apply 객체는 자신을 반환하기 때문에 client2에는 설정이 끝난 Client 객체가 들어감

### run

```kotlin
class Client {
    var token: String? = null
    fun connect() = println("연결됨")
    fun authenticate() = println("인증됨")
    fun getData(): String = "데이터"
}

val client = Client().apply { token = "abcd"}
fun main() {
    val result: String = client.run{
        connect()
        authenticate()
        getData() // 이 값이 result에 들어감
}
}
```

### also


## Lambda Expression with receiver

람다도 확장 함수처럼 수신 객체를 붙일 수 있음

* (Int) -> Unit
    * 일반 람다로 Int를 매개변수로 받음 -> 안에서 it 
* Int.() -> Unit
    * 수신 객체 람다로 Int가 수신 객채 -> 안에서 this 

```kotlin
MutableList<Int>.() -> Unit
이거는 수신 객체가 MutableList<Int> 이고, 괄호가 비어 있으니 매개변수는 없고 반환값도 없는 람다

fun String.bold()
이거와 형태가 똑같음
```

```kotlin
class Canvas {
    fun drawCircle() = println("원 그리기")
    fun drawSquare() = println("사각형 그리기")
}

fun render(block: Canvas.() -> Unit): Canvas {
    val canvas = Canvas()
    canvas.block()
    return canvas
}
```

1. render는 Canvas.() -> Unit의 람다를 block()으로 받음
2. 함수 안에서 Canvas 객체를 만들고, canvas.block()으로 람다를 실행하며, 이 때 canvas가 람다의 this가 됨
3. main에서 넘긴 람다 안에서는 drawCircle()을 Canvas 클래스 안에 있는 것처럼 바로 호출 가능

### Class and Interfaces

1. 코틀린은 기본적으로 상속이 안된다
2. 단일 상속만 된다. (부모 클래스는 1개만 사용 가능)
3. 모든 클래스의 최상위 조상은 Any라는 클래스로 기본 메소드가 다 들어가 있음

### 추상 클래스

```kotlin
abstract class Animal(val name: String) {
    abstract val sound: String
    
    fun introduce(){
        println("$name은 $sound하고 울어요")
    }
}

// 콜론 뒤에 부모 클래스를 쓰고, 부모 생성자에 필요한 값을 괄호로 넘김
// override 키워드를 통해 부모의 것을 자식이 구현할 수 있음
class Dog(name: String): Animal(name){
    override val sound = "멍멍"
}

fun main(){
    val dog = Dog("바둑이")
    dog.introduce()
}
```

### Interface

1. 인터페이스도 추상 클래스와 비슷하나, 생성자가 없고 객체도 못 만든다.
2. 상속 가능한 상태가 아니고 abstract도 안 붙여도 됨
3. 한 클래스가 여러 인터페이스를 구현도 가능

```kotlin
interface Flyable {
    fun fly()
}
interface Swimmable {
    val maxDepth: Int
    fun swim()
}
class Duck: Flyable, Swimmable {
    override fun fly() = println("날아요")
    override val maxDepth = 2
    override fun swim() = println("헤엄")
}
```

다만 인터페이스에 내용이 많으면 전부 다시 구현해야 하는 단점이 있는데, 이 때 보일러플레이트가 발생함

그래서 이걸 해결하고자 위임하는 코드가 있음

```kotlin
interface Printer {
    val prefix: String
    fun printLine(text: String)
    fun printTitle(text: String)
    fun info(): String
}

// 위임없으면 이렇게 다 구현
class BasicPrinter : Printer {
    override val prefix = "[기본]"
    override fun printLine(text: String) = println("$prefix $text")
    override fun printTitle(text: String) = println("== $text ==")
    override fun info() = "BasicPrinter"
}

// Printer 인터페이스 구현은 p에게 위임한다.
class MyPrinter(val p: Printer): Printer by p{
    override val prefix = "[커스텀]"
}
```

## Objects

object 키워드를 쓰면 클래스 선언과 객체 선언을 동시에 할 수 있음
이렇게 만들어진 객체는 프로그램 전체에서 딱 하나뿐이고 어디서든 쉽게 접근 가능클래스라고해서 싱글톤이라고 부름

Lazy 특성을 가지고 있어서, 접근하는 순간 만들어짐

```kotlin
object Logger {
    var count = 0
    fun log(message: String){
        count++
        println("$count $message")
    }
}
fun main(){
    Logger.log("start")
    Logger.log("login")
}
```

### 동반 객체 (Companion Object)

클래스 안에 넣는 특별한 object로, 클래스 당 하나만 가질 수 있음

안에 선언한 속성과 함수는 그 클래스의 모든 인스턴스가 공유

생싱시점은 클래스가 처음 참조될 때 (lazy)

```kotlin
class Pizza(val topping: String) {
    companion object {
        val maxSlices = 8
        fun describe() = println("모든 피자는 $maxSlices" 조각)
    }
}
fun main(){
    Pizza.describe()
    println(Pizza.maxSlices)
}
```


## Open and Special classes

코틀린은 기본적으로 상속이 안되지만, 그걸 허용하는 open이라는 문법이 있음

인터페이스나 추상클래스를 쓸 수 없는 상황에서 일반 클래스를 상속 가능하게 만들고 싶으면 open을 붙임

```kotlin
open class Animal(val name: String)

class Cat(name: String, val color: String): Animal(name)

fun main(){
    val cat = Cat("나비", "치즈")
    println(..)
}
```

클래스 내 함수도 덮어쓰기 할 수 있는데, 부모는 open / 자식은 override 하면 됨

변수의 경우, 덮어쓰기보다 생성자로 처음부터 넘기는게 좋다.

```kotlin
open class Animal(val name: String){
    open fun speak() = println("$name...") // 덮어쓰기 허용
    fun sleep() = println("zz") // 금지
}
class Cat(name: String): Animal(name){
    override fun speak() = println("$name ..")
}
```

### sealed - 자식 종류 제한

정해진 곳 안에서만 자식을 만들 수 있는 특별한 추상클래스로 when과 만나면 빛을 발함

왜냐하면 자식이 둘 뿐이라는 걸 알기 때문에 else가 필요 없음

```kotlin
sealed class Shape

class Circle(val radius: Double) : Shape()
class Rect(val width: Double, val height: Double): Shape()

fun area(shape: Shape): Double = when (shape){
    // is는 타입 연산자
    is Circle -> 3.14 * shape.radius * shape.radius
    is Rect -> shape.width * shape.width
    // else 필요없음
}
```

### inline value

값 하나를 잠깐 감싸는 작은 객체를 많이 만들면 성능에 부담 될 수 있음

inline value 클래스는 이 부담 없이 값을 감싸게 해주며, 한 개만 파라미터로 받을 수 있음

Inline value에 파라미터 두 개 넣으면 아래 에러 발생

Inline class must have exactly one primary constructor parameter.

```kotlin
@JvmInline
value class UserId(val id: Int)

fun findUser(userId: UserId){
    println("사용자 ${userId.id}")
}
fun main(){
    findUser(UserId(42))
}
```
