# 2026-11-12 변환 드릴 ② (Java → Kotlin, MemberService · SpringConfig)

## 소요 시간
- MemberService: 미기록
- SpringConfig: 미기록

## 틀린 것

| 틀린 것 | 맞는 것 | 메모 |
|---|---|---|
| `class MemberService(memberRepository: MemberRepository)` | `class MemberService(private val memberRepository: MemberRepository)` | 어제 Member 와 같은 실수. `val` 이 없으면 생성자 인자일 뿐이라 함수 안에서 안 보인다. **의존성도 주 생성자 프로퍼티** |
| `private` 생략 | `private val`, `private fun` | Kotlin 기본은 public |
| `return member.id` (반환 타입 `Long`) | `return member.id!!` | `member.id` 는 `Long?` |
| `fun findMembers(): List` | `List<Member>` | Kotlin 에는 꺾쇠 없는 raw 타입이 없다 |
| `@Bean` 메서드를 `val` 프로퍼티로 바꿈 | `@Bean fun memberService(): MemberService { ... }` | 규칙 과잉 적용. 아래 참고 |

## 한 번에 맞은 것
- `IllegalStateException("...")` — `new` 없이 생성
- `findOne(): Member?` — `Optional` 을 nullable 로
- `/* */` 주석 (어제 틀린 것)
- `memberRepository()` 반환 타입을 인터페이스로

## 새로 쓴 문법

**`ifPresent { }` → `?.let { }`**
```kotlin
memberRepository.findByName(member.name)?.let {
    throw IllegalStateException("이미 존재하는 회원입니다.")
}
```
`?.` 는 왼쪽이 null 이 아닐 때만 오른쪽을 실행한다. 어제 `store?.id` 는 `store` 가 null 일 수 없어서 틀렸고,
여기는 `findByName` 이 `Member?` 를 돌려줘서 맞다.

**`Long?` 를 `Long` 으로 만드는 세 가지**
| 방법 | 코드 | 언제 |
|---|---|---|
| 단언 | `member.id!!` | null 이 아니라는 근거가 바로 옆에 있을 때 (여기선 직전의 `save`) |
| 타입을 사실대로 | 반환 타입 `Long?` | 호출부가 null 을 처리해야 할 때 |
| 직접 처리 | `member.id ?: throw IllegalStateException("...")` | 같은 동작에 메시지를 붙이고 싶을 때 |

## 규칙 보정: 무엇을 프로퍼티로 접나

어제 규칙 "getter/setter 에 로직이 없으면 지운다"를 `@Bean` 메서드에 적용해서 틀렸다.

- 프로퍼티로 접는 것: 필드를 **그대로 꺼내거나 넣기만 하는** `getX` / `setX`
- `fun` 으로 옮기는 것: 그 밖의 모든 메서드. `memberService()` 는 객체를 **만들어서** 돌려주는 팩토리다
- `@Bean` 은 메서드에 붙는 어노테이션이고 스프링이 그 메서드를 호출한다

## 완성본

```kotlin
class MemberService(private val memberRepository: MemberRepository) {

    fun join(member: Member): Long {
        validateDuplicateMember(member)
        memberRepository.save(member)
        return member.id!!
    }

    private fun validateDuplicateMember(member: Member) {
        memberRepository.findByName(member.name)?.let {
            throw IllegalStateException("이미 존재하는 회원입니다.")
        }
    }

    fun findMembers() = memberRepository.findAll()
    fun findOne(memberId: Long) = memberRepository.findById(memberId)
}
```

```kotlin
@Configuration
class SpringConfig {
    @Bean
    fun memberService(): MemberService = MemberService(memberRepository())

    @Bean
    fun memberRepository(): MemberRepository = MemoryMemberRepository()
}
```

`memberRepository()` 의 반환 타입을 인터페이스로 써 두면 JPA 로 바꿀 때 오른쪽만 바꾸면 된다.
식 본문으로 타입을 생략하면 구현체 타입으로 추론된다.
